# AnimaPro: ревью и план подготовки надёжного учебного релиза

## 1. Итог ревью и границы проверки

**AnimaPro пока следует считать прототипом, а не готовым учебным релизом.** Основные части приложения уже есть, но найдены ошибки, затрагивающие сохранность работы и результат мультфильма.

Проверены исходный код, зависимости, инструкции и скрипты поставки. Выполнен `cargo test --offline --locked`: **4 теста прошли**. Форматирование и Clippy не проверены: соответствующие компоненты отсутствуют в установленном Rust. Интерактивная приёмка интерфейса, измерение производительности и запуск Windows-версии не проводились.

Принятая цель: **надёжное офлайн-приложение для школьников 4–5 класса на macOS и Windows**. Сохраняем Rust и egui. Звук, облако, совместную работу и импорт изображений откладываем до стабилизации базового сценария.

Приоритеты:

- **P1 — блокирует выпуск:** потеря данных, неверное видео, зависания и аварийное завершение.
- **P2 — необходимо для учебного релиза:** понятное управление, предсказуемая отмена, проверки и качественная поставка.
- **P3 — последующее развитие:** дополнительные возможности после приёмки.

## 3. План улучшений по аспектам

### Сохранение, открытие и восстановление — P1

- Ввести единый сценарий выхода из изменённого проекта: **«Сохранить / Не сохранять / Отмена»** перед новым проектом, открытием другого и закрытием приложения.
- Продолжать действие только после успешного сохранения. Отмена выбора файла и ошибка записи оставляют текущую работу открытой.
- Добавить «Сохранить как». Менять текущий путь только после успешной записи: отмена диалога не должна сбрасывать прежний путь.
- При успешной смене проекта очищать историю, выбор объектов и элементов, состояние редактора, незавершённые жесты; останавливать воспроизведение.
- Использовать уникальный временный файл рядом с целевым, завершение и синхронизацию записи перед заменой. При ошибке сохранять предыдущий исправный файл.
- Хранить восстановление в пользовательской папке приложения, отдельно для каждой сессии, с исходным путём и временем копии.
- Запускать автосохранение изменённого проекта каждые 30 секунд независимо от действий мышью. Запись выполнять в фоне по снимку состояния.
- При запуске предлагать восстановление с датой и именем проекта. Удалять только копию соответствующей сессии после успешного сохранения либо явного отказа от восстановления.

**Готово, когда:** отмена любого диалога безопасна; сбой сохранения не портит существующий файл; два запуска не перезаписывают восстановление друг друга; открытие B после A исключает перенос истории A.

### Геометрия, сцена и экспортируемый кадр — P1

- Ввести единое логическое пространство сцены **640×360**, начало координат объектов — в центре. Экспорт 1280×720 масштабирует всю сцену ровно вдвое.
- В окне вписывать сцену с сохранением пропорций 16:9. Размер окна не изменяет композицию.
- Построить общий слой геометрии для предпросмотра и экспорта: фигуры, штрихи, цвет, прозрачность, толщина, заливка и порядок объектов.
- Применять масштаб, затем поворот, затем перенос ко всем элементам. Использовать одинаковую геометрию эллипсов и прямоугольников в обоих выводах.
- Вычислять рамку выделения из преобразованной геометрии. Для попадания курсора переводить координаты обратно в локальные координаты объекта.
- Сохранять смещение между курсором и объектом при начале перетаскивания.
- Отличать пустой пользовательский рисунок от встроенной фигуры: пустой рисунок не должен неожиданно становиться прямоугольником.

**Готово, когда:** пользовательский рисунок, вытянутый овал, повёрнутый прямоугольник и перекрывающиеся объекты одинаково расположены в предпросмотре и видео; допустимы лишь небольшие различия сглаживания.

### Управление экспортом — P1

- Выделить экспорт в отдельную службу с состояниями: подготовка, запись кадров, завершение, успех, отмена, ошибка.
- До запуска проверять доступность FFmpeg и `libx264`; выдавать понятную причину невозможности экспорта.
- Читать stderr параллельно, сохраняя ограниченный объём последних сообщений.
- Управлять дочерним процессом независимо от передачи кадров, чтобы отмена могла остановить и заблокированную запись.
- На любом завершении закрывать потоки, дожидаться процесса и удалять собственный временный файл при неуспехе.
- Использовать уникальные имена временных файлов. Заменять существующий итоговый файл только после успешного кодирования.
- Показывать 100% только после завершения FFmpeg и публикации файла; до этого отображать «Завершаю видео».
- Экспортировать неизменяемый снимок проекта на момент запуска. Последующие правки не должны менять уже начатое видео.
- При закрытии приложения с активным экспортом предлагать дождаться или отменить его.

**Готово, когда:** отсутствие кодировщика, ошибка диска, остановка FFmpeg и отмена не оставляют зависших процессов и не повреждают ранее существовавшее видео.

### Формат проекта и обработка входных данных — P1

- Отделить чтение контейнера, разбор JSON, миграцию версии и проверку модели.
- Ввести формат v2 с явным видом содержимого объекта и размером сцены. Сохранять только v2; читать существующие ZIP-проекты v1 и старый JSON.
- Для v1 сохранять координаты и размеры предпросмотра; существующие `elements` трактовать как рисунок, пустые — как прежнюю встроенную фигуру.
- Неизвестную будущую версию отклонять с понятным сообщением, не изменяя открытый проект.
- Проверять уникальность идентификаторов, существование рисунков, порядок и уникальность времён поз, положительные размеры и толщины, конечность чисел.
- Ограничить длительность текущим диапазоном 1–60 секунд; позы должны находиться внутри длительности.
- Ввести защитные пределы: 32 МиБ распакованного JSON, 1 000 объектов и рисунков, 100 000 элементов, суммарно 1 миллион точек. Сообщать о превышении, не обрезать данные молча.
- Ограничивать чтение по фактическому объёму, а не только по размеру в заголовке ZIP.

**Готово, когда:** повреждённый или чрезмерно большой проект отклоняется контролируемо; набор старых проектов открывается без потери содержимого.

### История действий и состояние редактора — P2

- Ввести транзакции редактирования: начало жеста сохраняет исходное состояние, завершение фиксирует одно действие.
- Объединять движение ползунка, перетаскивание объекта и создание штриха в одну запись истории.
- Не добавлять историю, если данные не изменились; прерванный жест возвращать к исходному состоянию.
- На первом этапе оставить снимки проекта, ограничив историю 100 действиями и ориентировочным бюджетом 64 МиБ. Переход к отдельным командам изменений выполнять только при подтверждённой необходимости.
- Привязать признак несохранённых изменений к сохранённому состоянию истории: отмена до него возвращает статус «сохранено».
- После отмены проверять актуальность выбранного объекта, открытого рисунка и индекса выбранного элемента.
- Добавить стандартные сочетания клавиш для сохранения, отмены, повтора и воспроизведения; учитывать фокус текстовых полей.

**Готово, когда:** одно перетаскивание отменяется одним действием, а отмена удаления или создания рисунка не оставляет недействительных ссылок.

### Рисование и анимация — P2

- Отображать создаваемый штрих и контур фигуры до отпускания мыши; одиночный клик карандашом создаёт точку.
- Исправить эллипс, выделение и перенос элементов. Очистить состояние жеста при смене инструмента, рисунка и закрытии окна.
- Добавить управление позами: выбрать, создать, удалить и переместить по времени с шагом 0,1 секунды.
- При перемещении на занятую отметку отклонять действие с объяснением; замена существующей позы допускается отдельным явным действием.
- Предоставить переключатель «Плавно / Равномерно», который сейчас есть в модели, но недоступен пользователю.
- Добавить переименование и изменение порядка объектов «Вперёд / Назад».
- При изменении длительности ограничивать указатель времени новой границей. Сохранять существующий запрет сокращать фильм за последнюю позу и объяснять причину.

**Готово, когда:** весь сценарий создания движения доступен из интерфейса без редактирования файла проекта.

### Интерфейс, обучение и доступность — P2

- Создавать таймлайн до центральной панели; добавить прокрутку библиотеки и дорожек.
- Выровнять дорожки по общей шкале независимо от длины названия объекта.
- Разделить постоянный статус сохранения, подсказки и ошибки. Автосохранение не должно затирать важное сообщение.
- Заменить критичные кнопки из одиночных символов на понятные подписи; обеспечить видимый фокус и подсказки.
- Отключать недоступные действия, например отмену при пустой истории.
- Добавить краткий встроенный урок: добавить объект → поставить вторую позу → посмотреть → сохранить → сделать видео.
- Поддержать масштаб интерфейса, проверить кириллицу и отсутствие зависимости от отображения emoji.
- Проверить минимальное окно 1024×640, увеличенный системный масштаб, клавиатурную навигацию и доступные названия элементов.

**Готово, когда:** ребёнок может пройти базовый сценарий по встроенным подсказкам; существенные элементы доступны без обрезания и наведения мыши.

### Архитектура и сопровождаемость — P2

- Разделить монолит на модель проекта, анимацию, геометрию, хранение, историю, экспорт и интерфейс.
- Оставить точку входа ответственной только за запуск.
- Ввести внутренние интерфейсы: проверка и миграция проекта, вычисление состояния на момент времени, построение сцены, безопасное сохранение и управление экспортом.
- Использовать типизированные ошибки внутри приложения; переводить их в русские сообщения на границе интерфейса.
- Отделить состояние документа от временного состояния окон и инструментов.
- Зафиксировать версию Rust, добавить форматирование и Clippy в обязательные проверки.
- Не вводить плагины, сервер или публичный API: текущей задаче достаточно внутренних модулей. Внешнее изменение — версия формата проекта.

**Готово, когда:** модель, сохранение и экспорт проверяются без запуска окон, а изменения UI не требуют изменения хранения данных.

### Производительность и диагностика — P2

- Сначала измерить стоимость отрисовки, истории, автосохранения и экспорта; не считать замедления доказанными без замеров.
- Убрать полное клонирование библиотеки и повторное копирование списка сцены на каждом кадре.
- Кэшировать геометрию рисунков по версии изменения и индексировать поиск рисунков по идентификатору.
- Переиспользовать буфер экспортного кадра.
- Исключить непрерывную перерисовку в простое; оставлять запланированное пробуждение для автосохранения.
- Добавить локальный журнал ошибок с ограничением размера и команду копирования диагностической информации; не включать содержимое рисунков и полные пользовательские пути.
- Контрольная нагрузка: фильм 60 секунд, 50 объектов, 1 000 элементов и 20 000 точек. Цель — не менее 30 кадров/с предпросмотра и отзывчивый интерфейс при сохранении и экспорте на зафиксированной тестовой машине.

### Сборка, поставка и документация — P2

- Автоматизировать тесты на macOS и Windows, сборки Apple Silicon, Intel и Windows x64.
- Использовать зафиксированные зависимости и `--locked`; останавливать упаковку при любой ошибке.
- Собирать поставку в чистом временном каталоге, публиковать её только после проверок.
- Проверять архитектуру, запуск и наличие `libx264` у комплектного FFmpeg; выполнять короткий пробный экспорт.
- Проверять поставку на машинах без Rust и системного FFmpeg, включая пути с пробелами и кириллицей.
- Добавить значок, согласованные версии и сведения о сборке. Подписание и notarization оформить отдельным этапом публичного распространения с необходимыми учётными данными.
- Подготовить перечень зависимостей, их лицензий и сведения о конкретной поставляемой сборке FFmpeg.
- Переписать README по проверенным возможностям: убрать несоответствующие отметки готовности, описать восстановление и ограничения.
- Дополнить ручную приёмку сценариями отказов и добавить короткую памятку для учителя.

| Анимация | Нулевая и конечная отметки; одна и несколько поз; плавное и равномерное движение; кратчайший поворот; изменение длительности. |
| Геометрия | Все инструменты, настоящий эллипс, поворот, масштаб, прозрачность, перекрытие, выделение и движение без скачка. |
| Формат | Старые версии, неизвестная версия, повреждённый ZIP, отсутствующий JSON, неверные ссылки, дубли идентификаторов, превышение лимитов. |
| Экспорт | Проверка содержимого кадров; MP4 1280×720, 30 fps, без звука; длительность с допуском один кадр; отмена, отказ кодировщика, ошибка записи и замены файла. |
| Интерфейс | Разные размеры и масштаб экрана, длинные имена, много дорожек, переключение окон, горячие клавиши и фокус ввода. |
| Поставка | Чистые macOS Apple Silicon/Intel и Windows x64, отсутствие FFmpeg в PATH, запуск комплектного кодировщика. |

Для геометрии сравнивать контрольные изображения до кодирования, а экспортированный MP4 проверять отдельно с учётом потерь H.264. Для отказов экспорта использовать управляемый тестовый процесс, воспроизводящий ошибку, задержку и большой поток stderr.

**Условия выпуска:** закрыты все P1; проходят автоматические проверки; пройдена ручная приёмка обеих платформ; подтверждён сценарий «нарисовать → анимировать → сохранить → открыть → экспортировать».

## 5. Последовательность реализации

1. **Страховочная база:** добавить регрессионные проверки потери данных и неверного экспорта; выполнить минимальное разделение кода для тестирования.
2. **Сохранность работы:** переходы между проектами, история, безопасная запись, восстановление и проверка входных файлов.
3. **Правильный мультфильм:** единая геометрия, поворот, формат v2, соответствие предпросмотра и видео, надёжное управление FFmpeg.
4. **Учебный интерфейс:** рисование, позы, порядок объектов, таймлайн, подсказки и доступность.
5. **Подготовка выпуска:** измерения, оптимизация подтверждённых проблем, автоматические сборки, чистая поставка и документация.

Каждый этап заканчивается своими проверками и отдельным проверяемым результатом. Новые крупные функции остаются за пределами этого релиза; переход к ним — после подтверждения сохранности проектов и корректности видео.
