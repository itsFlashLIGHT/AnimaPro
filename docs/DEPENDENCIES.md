# Зависимости и подготовка поставки

[THIRD_PARTY_DEPENDENCIES.tsv](THIRD_PARTY_DEPENDENCIES.tsv) содержит названия, версии, строки лицензий и ссылки на исходные репозитории сторонних пакетов из `Cargo.lock`. Список получен из метаданных Cargo и намеренно включает зависимости всех разрешённых платформ и сборочных инструментов: конкретный исполняемый файл использует не обязательно все строки. Строки лицензий приведены как указаны авторами пакетов; они не заменяют тексты лицензий и не являются подтверждением достаточности уведомлений для распространения. Сам AnimaPro распространяется по [лицензии MIT](../LICENSE); она не изменяет лицензии сторонних компонентов.

После изменения зависимостей обновите список и контрольную сумму:

```sh
python3 scripts/update-dependency-report.py
python3 scripts/update-dependency-report.py --check
```

На машине с уже загруженными зависимостями можно добавить `--offline`. Скрипт проверяет неизменность `Cargo.lock`; он требует Python 3 и Cargo. Скрипты упаковки останавливаются, если контрольная сумма перечня не соответствует `Cargo.lock`.

## FFmpeg

FFmpeg не хранится в репозитории: сборщик поставки выбирает конкретный исполняемый файл. Вместе с ним необходимо передать папку, содержащую как минимум непустые `FFMPEG-LICENSE.txt` и `FFMPEG-SOURCE.txt`. В материалах нужно идентифицировать выбранную сборку, её лицензионные тексты и сведения об исходном коде и способе его получения. Дополнительные уведомления о компонентах сборки можно положить в ту же папку. Содержимое предоставленных материалов требуется проверить для выбранной сборки; проверка наличия файлов не проверяет их полноту.

Сборка FFmpeg с libx264 использует компоненты под GPL; лицензия MIT самого AnimaPro не заменяет условий для FFmpeg и его зависимостей. См. [документацию FFmpeg об x264](https://ffmpeg.org/general.html#x264) и [сведения FFmpeg о лицензировании](https://ffmpeg.org/legal.html). Для выбранных двоичных файлов необходимо установить точные исходные версии и изменения всех включённых компонентов, способ сборки и комплект материалов для распространения. Страница [загрузок FFmpeg](https://ffmpeg.org/download.html) ссылается на сторонние двоичные сборки; сам проект FFmpeg распространяет исходный код.

macOS-упаковщик копирует только исполняемый файл FFmpeg и отклоняет внешние динамические библиотеки за пределами системных путей для обеих архитектур. Например, локальная сборка Homebrew с зависимостями в `/opt/homebrew` для такой поставки не подходит. Это проверка прямых зависимостей, а не подтверждение работы на чистой машине. Windows-поставку также необходимо проверить на чистой машине без дополнительных DLL.

13 ноября 2026 года подготовлена локальная экспериментальная универсальная сборка FFmpeg 9.0.2 с x264 и пакет `dist/AnimaPro.app`. В папку пакета включены точные исходные архивы FFmpeg и x264, тексты GPL и параметры сборки; SHA-256 включённого FFmpeg: `e387e06b1ce780525f6afacce6056cdcb83750069ec31df0fc0cdb3666b38ce5`. Подпись исходного архива FFmpeg проверена с помощью PGPy 0.6.0; отпечаток ключа совпал с [опубликованным FFmpeg](https://ffmpeg.org/download.html#release-verification). PGPy предупредил, что проверка отзыва и самоподписей ключа им не выполняется. Оба среза прошли локальный сквозной тест экспорта, Intel — через Rosetta. Это не подтверждает лицензирование всей поставки, запуск на чистых машинах или публичную готовность.

Также подготовлен экспериментальный Windows x64 комплект `dist/AnimaPro-windows-x64-experimental.OkuwimZ1`, собранный на macOS с llvm-mingw 20261104. В нём лежат приложение, самостоятельно собранный FFmpeg, требуемый приложению `libunwind.dll`, тексты лицензий и исходники FFmpeg и x264. Инструмент LLVM подтвердил архитектуру файлов, наличие значка и прямые зависимости; работа на Windows ещё не проверена. Это отдельная кросс-сборка GNU LLVM, не результат стандартного MSVC-упаковщика. До распространения нужно проверить точные исходники и условия используемых библиотек времени выполнения, полный комплект уведомлений и работу всех функций на чистой Windows.

В `third-party-sources` этого комплекта дополнительно сохранены исходники LLVM 23.1.5, скрипты llvm-mingw 20261104 и архив MinGW-w64 для ревизии, используемой в этих скриптах по умолчанию. Контрольная сумма архива LLVM совпадает с [публикацией проекта LLVM](https://github.com/llvm/llvm-project/releases/expanded_assets/llvmorg-23.1.5); подпись архива не проверялась. Версия MinGW-w64 могла быть переопределена при сборке готового инструментария, поэтому точное соответствие библиотекам комплекта пока не подтверждено. Рядом с архивами записаны контрольные суммы и сведения об источниках.

Для повторной подготовки Windows-кодировщика на macOS добавлен `scripts/build-ffmpeg-windows-cross.sh`: он принимает архивы исходников, каталог llvm-mingw и новый выходной каталог. Скрипт проверяет контрольные суммы исходников, версию компилятора, необходимые компоненты FFmpeg, архитектуру и прямые DLL-зависимости. Он собрал второй предварительный кодировщик в `dist/ffmpeg-windows-rebuilt`; побайтовая воспроизводимость не проверялась. Ни один из двух Windows-кодировщиков ещё не запускался на Windows.

Скрипт упаковки включает эту папку, список зависимостей и `BUILD-INFO.txt` с версией приложения, версией Rust, SHA-256 включённого FFmpeg и выводом его команд `-version`, `-buildconf` и `-L`. Таким образом запись привязана к фактически скопированному бинарнику. До публичного распространения необходимо также проверить применимые условия всех включённых компонентов, доступность соответствующих исходников и правильность уведомлений.

## Подписание

Текущие скрипты создают неподписанную поставку. Подписание, notarization и публичное распространение требуют отдельной настройки и учётных данных; они не выполняются автоматически и не проверялись. Готовые сборки следует проверить на чистых машинах macOS Apple Silicon, macOS Intel и Windows x64, в том числе без Rust и системного FFmpeg.
