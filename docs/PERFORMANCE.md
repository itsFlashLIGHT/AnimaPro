# Контрольное измерение производительности

Измерение воспроизводится командой:

```bash
cargo test --offline --locked --release performance_measurement::control_workload -- --ignored --nocapture
```

Нагрузка: проект длительностью 60 секунд, 50 объектов, 50 разных рисунков, всего 1 000 штрихов и 20 000 точек. Тест измеряет построение кадров и элементов интерфейса в памяти без настоящего окна, GPU и видеокодирования, копирование снимка проекта и одну запись проекта в локальную временную папку. Показатели являются средними для нескольких кадров, кроме одной записи; это не тест частоты настоящего интерфейса или длительной нагрузки.

На проверенной машине MacBook Pro с Apple M4, 16 ГБ памяти, macOS 27.0.1 и Rust 1.90.0 получены следующие ориентировочные результаты:

| Измерение | До повторного использования | После |
| --- | ---: | ---: |
| Кадр 640×360 | 14,14 мс | 13,54 мс |
| Кадр 1280×720 | 23,28 мс | 23,13 мс |
| Снимок проекта | 0,02 мс | 0,02 мс |
| Запись проекта | 14,12 мс | 13,86 мс |

Разница невелика и один запуск не доказывает устойчивого ускорения. После изменения пиксельный буфер и локальные контуры рисунков повторно используются, а неизменившийся кадр не загружается заново при перерисовке элементов управления. Для соответствия целевым 30 кадрам/с ещё нужно измерить настоящий предпросмотр с интерфейсом, а также его отзывчивость при одновременных автосохранении и экспорте на фиксированных macOS- и Windows-машинах.

После добавления проверки допустимости изменений отдельное контрольное измерение на той же машине показало 0,57 мс на проверку проекта и 0,60 мс на изменение позы с проверкой. Это среднее для 20 операций без интерфейса; отзывчивость в окне при сохранении и экспорте остаётся непроверенной.

Повторный запуск 12 ноября 2026 года на текущем коде: 12,97 мс на кадр 640×360, 25,61 мс на кадр 1280×720, 0,02 мс на снимок, 0,60 мс на проверку, 0,63 мс на изменение позы с проверкой и 8,65 мс на запись. Это одно измерение без окна и кодирования, не подтверждающее целевые 30 кадров/с в интерфейсе.

После добавления построения интерфейса повторный запуск на той же машине показал 12,53 мс на кадр интерфейса со сценой при окне 1024×640 и изменении времени; отдельно отрисовка сцены заняла 12,93 мс. Это средние значения разных серий, поэтому их нельзя вычитать друг из друга. Окно, отображение на экране, работа GPU и одновременный экспорт не измерялись.

Дополнительная команда `cargo test --offline --locked --release concurrent_background_workload -- --ignored --nocapture` запускает на той же нагрузке настоящий FFmpeg и фоновую запись автокопии, строит 20 кадров интерфейса в памяти, проверяет наличие автокопии и отменяет экспорт. На том же Mac один запуск дал среднее 13,53 мс, максимум 15,95 мс; запись автокопии ещё выполнялась в начале одного кадра. Измерение не включает настоящее окно, GPU или действия пользователя и не подтверждает отзывчивость готовой поставки.

## Плотная дорожка поз

Дополнительный тест `cargo test --offline --locked --release dense_track_workload -- --ignored --nocapture` создаёт одну дорожку со 100 000 поз. На той же машине один запуск показал в среднем 0,11 мкс для поиска состояния по отсортированной дорожке против 77,20 мкс у последовательного поиска, 14,60 мкс на выбор отметок для шкалы шириной 600 логических пикселей и 0,12 мс на построение кадра интерфейса без окна и GPU. Эти значения относятся к искусственной нагрузке и не заменяют измерение реальной отзывчивости приложения.

Для плотной дорожки выводится ограниченное число видимых отметок, но при выборе используется полный список поз; список и дорожки создают элементы интерфейса только для видимой области.

## Общий рисунок у нескольких объектов

Команда `cargo test --offline --locked --release shared_asset_comparison_measurement -- --ignored --nocapture` измеряет только сравнение данных рисунка, без отрисовки. На указанном Mac 50 сравнений рисунка из 20 000 точек заняли в среднем 0,414 мс, одно — 0,011 мс. Теперь за кадр содержимое общего рисунка сравнивается один раз, даже если его используют несколько объектов. Это микробенчмарк; он не измеряет затраты на поиск и не подтверждает ускорение полного кадра или интерфейса.

## Измерение после визуальной доработки

17 ноября 2026 года повторены те же тесты в оптимизированной сборке на текущем Mac. Контрольный проект содержит 50 объектов, 1 000 штрихов и 20 000 точек. Один запуск дал 18,37 мс на отдельный кадр 640×360, 22,68 мс на кадр 1280×720 и 12,94 мс на построение кадра интерфейса со сценой без окна. Прежние отдельные измерения для сравнения приведены выше: 12,93 мс для кадра 640×360 и 12,53 мс для интерфейса со сценой. Значения получены в отдельных сериях; по одному запуску нельзя установить причину или устойчивость разницы.

Команда `cargo test --offline --locked --release preview_texture_preparation_cost -- --ignored --nocapture` отдельно измеряет преобразование готового буфера и постановку обновления текстуры в очередь egui. В одном запуске получено 0,097 мс для 640×360 и 0,378 мс для 1280×720. Перенос данных на GPU эта проверка не измеряет. Для дорожки со 100 000 поз команда `dense_track_workload` показала 8,65 мкс на выбор отображаемых маркеров и 0,05 мс на построение интерфейса в памяти; это искусственная нагрузка, не измерение взаимодействия пользователя.

Все эти значения относятся к работе в памяти. Частота кадров и задержки ввода в реальном окне, загрузка текстур на GPU и работа на Windows в этом цикле не измерялись; они не подтверждаются приведёнными числами.

Дополнительный запуск `concurrent_background_workload` с FFmpeg и фоновой автокопией дал в памяти в среднем 12,93 мс на кадр и максимум 13,48 мс среди 20 кадров; автокопия ещё выполнялась в начале одного кадра. Это короткое измерение не заменяет проверку окна и длительной работы.

Повторный запуск `shared_asset_comparison_measurement` после визуальной доработки дал 0,404 мс для 50 сравнений рисунка из 20 000 точек и 0,008 мс для одного сравнения. Проверка не включает отрисовку, поиск в кэше или работу окна и не является измерением полного кадра.
